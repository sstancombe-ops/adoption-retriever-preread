Rule of thumb for stakeholders: if the Adoption column on the Checklist is blank, we can still index content for Onboarding / shared pool — we should not claim Adoption SubAgent go-live for that cloud.

1 · Decision layers

Same filter family for Adoption and Onboarding — different values (especially order age) and different cloud readiness.

Layer 1
Cloud / product Sales · Service · FINS · AF & DC · later clouds
Layer 2
Contract & order Activated · provisioned · qty > 0 · not courtesy/reseller/OEM
Layer 3
Product taxonomy L1–L4 business / product line / family (+ SKU include/exclude)
Layer 4
Tenure gate Adoption: typically >90 days (renewals carve-out). Onboarding: ≤90 days.
Layer 5
Guidance path CSS unused-feature signals → avenue / checklist step · retriever id=

2 · Adoption vs Onboarding (side by side)

Adoption eligibility

  • Intent: existing customers with unused features
  • Order start date: >90 days or ≤90 with renewal/add-type carve-outs
  • Sept experience: FINS (filters filled; UAT 9/10 · Prod 9/25)
  • AF & DC: eligibility columns still blank → experience not ready; content may still index
  • Retriever ids (sheet): FINS id=ind.fsc · AF/DC id=ai + id=data.c360

Onboarding eligibility

  • Intent: new / recently purchased customers
  • Order start date: ≤90 days
  • Sept experience: Agentforce & Data Cloud nested in Sales/Service Phase 4 (UAT 9/10 · Prod 9/25)
  • FINS onboarding: sheet targets Oct (not Sept experience)
  • SKU nuance: use-case entitlements (Coworker / Pipeline / Account Mgmt / Service Assistant) + Data 360 prerequisite
Shared fields when filled: Contract Status = Activated · Order status = Activated/Provisioned · Available Qty > 0 · Reduction Order = False · exclude Courtesy / Reseller / OEM (and related product-name exclusions).
